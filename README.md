# 모듈별 개별 테스트 (test/module-consoles 브랜치)

도어·계기판·조명·와이퍼 모듈을 **하나씩 따로** 실행해 보는 대화형 콘솔입니다.
입력값을 직접 넣어 가며 그 모듈의 출력이 어떻게 바뀌는지 바로 확인합니다.

- 콘솔은 해당 모듈의 `step` 함수만 호출합니다. 다른 모듈은 실행되지 않으므로 **그 모듈 코드만** 확인할 수 있습니다.
- 센서 고장(C2), 유효한 속도(C3), 수신 중단(C4) 판정은 실제와 같은 `common.c`가 합니다.
- emsdk 없이 `gcc`와 `make`만 있으면 됩니다.

> 전체 시스템을 함께 돌려 보는 시뮬레이터(브라우저)는 `develop` 브랜치 README를 보세요.

## 1. 준비
Windows는 **WSL Ubuntu 안에서** 진행합니다.
```bash
sudo apt update && sudo apt install -y build-essential git      # gcc, make
gh repo clone taesik-lee303/vehicle-body-control                # 처음 받는 경우
cd vehicle-body-control
git fetch origin
git checkout test/module-consoles
make test                                                       # ALL TESTS PASSED 확인
```

## 2. 실행
```bash
make con-doors       # 도어·잠금 D1~D3
make con-dashboard   # 계기판 경고 D4·D5
make con-lighting    # 조명 L1~L6
make con-wipers      # 와이퍼 W1~W5
```
처음 실행하면 빌드한 뒤 바로 콘솔이 열립니다. 끝낼 때는 `q`.

## 3. 화면 읽는 법
```
== 도어·잠금 (D1~D3) ==  시각 0.000초
  [출력] 도어 풀림 |                                       ← 이 모듈의 출력
  [판정] 수신 중단 아니오 | 시동 켜짐 | 유효한 속도 14 km/h  ← 모듈이 실제로 받는 값 (C2~C4 반영)
  [입력 바꾸기]
    1) 시동 [ON] (누르면 전환)                               ← [ ] 안은 지금 보내고 있는 값
    2) 기어 [D]
    3) 속도 [14 km/h] (유효 0~250)
    4) 속도·기어·시동 송신 [보내는 중] (누르면 끊기/잇기, C4)
  [시간·기타]  t) 시간 진행   r) 처음 상태로(C5)   h) 도움말   q) 종료
선택> 3
  속도 km/h (범위 밖 값도 됨, 예: 300)> 15
  → [  0.000s] 도어: 풀림 → 잠김                           ← 바뀐 출력과 그 시각
```
출력이 바뀌지 않으면 `→ 출력 변화 없음`이 나옵니다.

## 4. 조작
| 입력 | 하는 법 |
|---|---|
| 메뉴 번호 | 바꿀 입력을 고릅니다 |
| 숫자 값 (속도·조도·강우량) | 정수를 입력합니다. 범위 밖 값(`300`, `70000`, `101`, `-5`)도 그대로 보내집니다 |
| 보기 (기어·스위치·도어·와이퍼 단계) | 번호나 이름으로 고릅니다. 예: `4` 또는 `D`, `AUTO`, `저속`, `FL`, `열림` |
| 시동, 송신 끊기 | 누를 때마다 켜기/끄기, 끊기/잇기가 바뀝니다 |
| `t` | **시간 진행.** 0.05초 단위로 입력합니다 (`0.95`, `0.05`, `3`) |
| `r` | 처음 상태(C5), 시각 0으로 |
| `h` | 이 콘솔의 요구사항 요약과 도움말 |
| 그냥 Enter | 값을 묻는 곳에서는 취소 |

- **시간은 `t`로만 흐릅니다.** 입력을 바꾸면 그 시각에 바로 반영되고, 시간이 흐르는 동안 속도·기어·시동·조도·강우량은 0.05초마다 자동으로 다시 보내집니다(사양서 3.1).
- 송신을 끊으면 **0.5초가 지나야** 수신 중단·센서 고장으로 판정됩니다. 끊은 뒤 `t`로 시간을 진행하세요.
- 경계 시각은 나눠서 진행하면 잘 보입니다. 예: `t 0.95` → 아직, `t 0.05` → 1.000초에 바뀜.

## 5. 콘솔별 입력과 테스트 방법

### 도어·잠금 (`make con-doors`)
| 메뉴 | 1 시동 | 2 기어 | 3 속도 | 4 속도·기어·시동 송신 |
|---|---|---|---|---|

출력: 도어 잠김/풀림. 판단 순서: D1 수신 중단이면 그대로 → D2 시동 OFF 또는 기어 P면 해제 → D3 유효한 속도 15 km/h 이상이면 잠금 → 그 외 직전 유지.

| 순서 | 입력 | 기대 결과 | 요구사항 |
|---|---|---|---|
| 1 | `1`(시동 ON), `2`→`D`, `3`→`14` | 풀림 | D3 (15 미만) |
| 2 | `3`→`15` | **잠김** | D3 (15 이상) |
| 3 | `3`→`5` | 잠김 유지 | D3 직전 유지 |
| 4 | `4`(송신 끊기), `t`→`0.5`, `1`(시동 OFF) | 수신 중단, **잠김 유지** | D1 |
| 5 | `4`(송신 잇기) | **풀림** (시동 OFF 반영) | D2 |
| 더 해 볼 것 | 기어 `P`, `N`, `R` / 속도 `300`(범위 밖) | P면 풀림, N은 유지, R도 15 이상이면 잠김, 300은 유효하지 않아 잠그지 않음 | D2, D3, C3 |

### 계기판 경고 (`make con-dashboard`)
| 메뉴 | 1 속도 | 2 조도 | 3 강우량 | 4 도어 | 5 차량 상태 송신 | 6 조도 송신 | 7 강우 송신 |
|---|---|---|---|---|---|---|---|

출력: 계기판 경고 (없음 / 주행 중 도어 열림 / 조도 센서 고장 / 강우 센서 고장). 시동 ON·기어 D로 시작합니다(유효한 속도 판정에 필요).

| 순서 | 입력 | 기대 결과 | 요구사항 |
|---|---|---|---|
| 1 | `4`→`FL`→`열림` (속도 0) | 경고 없음 | D4 (속도 > 0 아님) |
| 2 | `1`→`1` | **주행 중 도어 열림** | D4 |
| 3 | `2`→`70000` | 그대로 도어 경고 | D5 (도어 > 조도) |
| 4 | `4`→`FL`→`닫힘` | **조도 센서 고장** | D5 |
| 5 | `3`→`101` | 그대로 조도 | D5 (조도 > 강우) |
| 6 | `2`→`30000`, `3`→`0` | 강우 센서 고장 → 없음 | D5 |
| 7 | 문 열고 `5`(송신 끊기), `t`→`0.5` | 도어 경고 사라짐 | C3, D4 |

### 조명 (`make con-lighting`)
| 메뉴 | 1 시동 | 2 조도 | 3 조명 스위치 | 4 스위치 코드 | 5 와이퍼 단계 | 6 차량 상태 송신 | 7 조도 송신 |
|---|---|---|---|---|---|---|---|

출력: 전조등, 조도 고장 표시. 우선순위: L1 > L5 > L4 > L6 > L2·L3.
와이퍼 모듈은 실행하지 않습니다. L6은 **5) 와이퍼 단계**를 직접 바꿔 확인합니다.

| 순서 | 입력 | 기대 결과 | 요구사항 |
|---|---|---|---|
| 1 | `1`(시동 ON), `3`→`AUTO`, `2`→`300`, `t`→`0.95` | 아직 꺼짐 | L2 |
| 2 | `t`→`0.05` | **1.000초에 켜짐** | L2 (1초 연속) |
| 3 | `2`→`30000`, `t`→`2.95`, `t`→`0.05` | 3초 뒤 **꺼짐** | L3 (3초 연속) |
| 4 | `2`→`1200`, `t`→`5` | 직전 상태 유지 | L3 (1000~1500) |
| 5 | `2`→`30000`(낮), `5`→`저속`, `t`→`9.95`, `t`→`0.05` | 낮인데도 10초 연속 작동 → **켜짐** | L6 |
| 6 | `5`→`정지` | **바로 꺼짐**. 밝음(1500 초과) 3초를 L6이 켜 두는 동안에도 계속 셌기 때문 | L6, C1, L3 |
| 7 | `3`→`OFF`, `2`→`70000` | **켜짐 + 조도 고장 표시** | L5 > L4 |
| 8 | `1`(시동 OFF) | 꺼짐, 고장 표시는 유지 | L1, L5 |

### 와이퍼 (`make con-wipers`)
| 메뉴 | 1 시동 | 2 속도 | 3 강우량 | 4 와이퍼 스위치 | 5 스위치 코드 | 6 차량 상태 송신 | 7 강우 송신 |
|---|---|---|---|---|---|---|---|

출력: 와이퍼 단계(정지·간헐·저속·고속), 강우 고장 표시. 우선순위: W1 > W4 > W5 > W2·W3. 기어 D로 시작합니다.

| 순서 | 입력 | 기대 결과 | 요구사항 |
|---|---|---|---|
| 1 | `1`(시동 ON), `4`→`AUTO`, `2`→`30`, `3`→`9` | 정지 | W2 (<10) |
| 2 | `3`→`10`, `40`, `70` | 간헐 → 저속 → 고속 | W2 경계 |
| 3 | `2`→`0` | 고속 → **저속** | W3 (정차 시 한 단계 낮춤) |
| 4 | `3`→`101` | **간헐 + 강우 고장 표시** (정차여도 안 낮춤) | W5 |
| 5 | `1`(시동 OFF) | 정지, 고장 표시 유지 | W1 |
| 6 | `4`→`LOW`/`HIGH`/`OFF` (시동 ON) | 비와 관계없이 저속/고속/정지 | W4 |
| 7 | 강우 정상 값 후 `7`(송신 끊기), `t`→`0.45`, `t`→`0.05` | 0.5초에 고장 | C2 |

## 6. 규격 밖 값 넣기
모듈이 정해진 규격 밖의 값을 받았을 때 어떻게 동작하는지 확인할 수 있습니다.

| 입력 | 넣을 수 있는 값 | 넣을 수 없는 값 |
|---|---|---|
| 속도, 조도, 강우량 | 정수 전체(int32, 약 ±21억). 예: `-5`, `101`, `99999999` | 소수(`50.5`), 글자(`abc`), int32 밖 — 모듈 입력 형식이 정수라 넘길 방법이 없음 |
| 와이퍼 스위치 | **5) 스위치 코드**: 0 OFF, 1 AUTO, 2 LOW, 3 HIGH, 그 밖의 값도 그대로 (`7`, `-1`) | 글자 |
| 조명 스위치 | **4) 스위치 코드**: 0 OFF, 1 AUTO, 2 ON, 그 밖의 값도 그대로 | 글자 |

정해진 값 밖의 스위치는 메뉴에 `정의 안 됨(7)`처럼 표시됩니다.

확인해 본 결과 (develop 기준 코드)
| 콘솔 | 입력 | 동작 | 근거 |
|---|---|---|---|
| 와이퍼 | AUTO·강우 50%(저속)에서 스위치 코드 `7`, `-1` | 저속 유지 (마지막 정상 값 AUTO로 계속) | 팀 요구사항 SWR-W4-005 |
| 와이퍼 | HIGH에서 코드 `99`, 강우 `99999999` | 고속 유지, 강우 고장 표시만 켜짐 | SWR-W4-005, W4 > W5 |
| 조명 | ON(켜짐)에서 스위치 코드 `7`, 이후 조도 300·30000 | 켜짐 그대로 유지, 조도에 반응 없음 | 사양서·팀 문서에 정의 없음 → 질의 후보 |

## 7. 예제 파일로 한 번에 돌리고 기록 남기기
`tools/consoles/examples/`에 위 5절 순서를 적어 둔 입력 파일이 있습니다. 한 줄이 한 번의 입력이고, `#`로 시작하는 줄은 설명입니다.
```bash
make consoles
./build/con_doors     < tools/consoles/examples/doors.txt
./build/con_dashboard < tools/consoles/examples/dashboard.txt
./build/con_lighting  < tools/consoles/examples/lighting.txt
./build/con_wipers    < tools/consoles/examples/wipers.txt

# 결과를 파일로 남기기 (발표·verification.md 증거용)
./build/con_wipers < tools/consoles/examples/wipers.txt > wipers_결과.txt
# 바뀐 출력만 보기
./build/con_wipers < tools/consoles/examples/wipers.txt | grep -E "^# |→ \["
```
예제를 복사해 내 입력으로 고치면 나만의 테스트 기록이 됩니다. 입력한 값도 결과에 함께 찍힙니다.

## 8. 결과가 이상할 때
| 증상 | 확인 |
|---|---|
| 송신을 끊었는데 판정이 그대로 | 0.5초가 지나야 판정됩니다. `t`→`0.5` |
| 조명이 AUTO인데 조도에 반응이 없음 | 시간을 진행했는지(`t`). L2는 1초, L3는 3초 연속이어야 합니다 |
| 와이퍼가 정차해도 안 낮아짐 | 강우 고장 중이면 W5가 우선이라 낮추지 않습니다. `[판정]`에서 유효한 속도가 0인지도 확인 |
| 계기판 도어 경고가 안 뜸 | `[판정]` 유효한 속도가 0이거나 "없음"이면 D4가 성립하지 않습니다 |
| 사양서와 다르게 동작 | 콘솔 기록(입력과 `→` 줄)을 복사해 담당자에게 전달하고, `docs/verification.md` "AI가 틀린 곳"이나 결함 기록에 남깁니다 |
