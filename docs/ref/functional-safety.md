# 기능안전과 HARA 참고 (ISO 26262)

> 출처: 멀캠 강의자료 `참고자료_HARA` (Synetics, 26쪽). 슬라이드 상당수가 그림이라 텍스트로 확인된 부분(HAZOP 가이드워드, 실습 예, ASIL 결정 순서)만 근거로 삼았다.
> 표준 자체의 표(ASIL 결정표)는 강의 자료에서 그림으로만 있어 ISO 26262-3의 일반적인 내용으로 보충했고, 해당 부분에 `[표준 보충]`을 붙였다.
> **이 문서는 학습·설명용 참고다. VBC 사양서(VBC-SRS-001)에는 ASIL·안전 목표가 없다. 요구사항의 근거는 사양서이며, 여기 내용을 근거로 동작을 바꾸지 않는다.**

## 1. 기능안전 기본
- 기능안전: 전기·전자 시스템의 **오동작(malfunction)** 때문에 생기는 위험을 허용 가능한 수준으로 낮추는 활동. ISO 26262가 도로 차량(승용차·상용차·이륜차 포함, 3.5t 제한 없어짐 — 2판)에 적용된다. (p.3)
- 핵심 흐름: **오동작 → 위험(Hazard) → 위험사건(Hazardous Event) → ASIL → 안전 목표(Safety Goal) → FSR → TSR → SW 요구사항**.
- 결함 전파(Fault Propagation): 하위 요소의 결함이 상위 요소 고장으로 이어지는 경로를 따진다. 안전 등급이 높은 요소와 낮은 요소는 서로 간섭하지 않게 분리한다(Freedom from Interference). (p.9)
- 최종 ASIL은 위험사건 중 **가장 높은 등급**을 시스템에 부여한다. (p.20)

## 2. HARA 수행 절차 (p.11~12)
1. **Hazard 분석**: 기능별 오동작 식별(HAZOP) → 운행 상황(Operational Situation)과 결합해 위험사건 정의
2. **Risk 평가**: 위험사건마다 S(심각도), E(노출도), C(통제 가능성) → ASIL
3. **안전 목표**: 위험을 막는 최상위 요구. 위험사건에 대응해 "…를 방지해야 한다" 형식으로 쓴다.

### 2.1 HAZOP 가이드워드 → 오동작 (p.14~15)
| 가이드워드 | 의미 | 강의 예(자율주행 긴급 정지) |
|---|---|---|
| Loss of Function | 기능 상실 | 긴급 정지가 안 됨 |
| More Than Requested | 요구보다 과함 | 정지 시간이 길어짐(제동 거리 이상) |
| Less Than Requested | 요구보다 부족 | 정지 시간이 짧음 |
| Wrong Direction | 반대 방향 | 속도 증가 |
| Unintended Activation | 의도하지 않은 동작 | 의도치 않은 긴급 정지 |
| Failure to update as intended | 갱신 안 됨 | 기능이 잠겨 버림(Lock) |

### 2.2 운행 상황 (p.16~18)
위치(시가지·비시가지·주차장) × 도로(빗길·내리막·눈길) × 주행(직진·좌회전) × 차량 속도 구간을 조합하고, 그중 **최악 상황 3개**를 골라 위험사건으로 정의한다.

### 2.3 ASIL 결정 (p.20~25)
- S: 상해 심각도(S0~S3, AIS 기준 — p.21의 주석). E: 노출도(E0~E4). C: 통제 가능성(C0~C3).
- 강의 실습 결과:

| 상황 | 해저드 | S | E | C | 강의 ASIL |
|---|---|---|---|---|---|
| 비시가지·빗길·직진·고속(>100) | 의도치 않은 차량 움직임 | 3 | 4 | 3 | D |
| 시가지·내리막·직진·중속(30~60) | 의도치 않은 차량 움직임 | 3 | 3 | 3 | C |
| 주차장·눈길·좌회전·저속 | 차량 움직임 제어 불가 | 3 | 2 | 3 | C (※) |

> ※ ISO 26262-3 표에서 S3·E2·C3은 **B**다. 슬라이드의 C는 표기 오류이거나 다른 가정일 수 있다. 인용 전 확인한다.

`[표준 보충]` ASIL 결정표 (QM = 품질관리만, 안전 요구 없음)

| | C1 | C2 | C3 |
|---|---|---|---|
| S1·E1~E2 | QM | QM | QM |
| S1·E3 | QM | QM | A |
| S1·E4 | QM | A | B |
| S2·E1 | QM | QM | QM |
| S2·E2 | QM | QM | A |
| S2·E3 | QM | A | B |
| S2·E4 | A | B | C |
| S3·E1 | QM | QM | A |
| S3·E2 | QM | A | B |
| S3·E3 | A | B | C |
| S3·E4 | B | C | D |

암기 규칙: S+E+C 합이 10이면 D, 9이면 C, 8이면 B, 7이면 A, 6 이하면 QM (S1~S3, E1~E4, C1~C3 기준).

- 안전 목표 예(강의): "의도치 않은 차량의 움직임을 방지해야 한다." (p.25)

## 3. 이후 단계 (강의 `교육정리`·SW 테스팅 교재와 연결)
| 단계 | 내용 |
|---|---|
| 안전 목표 → FSR | 안전 목표를 달성하는 기능 수준 요구(감지·반응·안전 상태·허용 시간 FTTI) |
| FSR → TSR | 구현 가능한 기술 요구(센서 이중화, 타임아웃, 범위 검사 등) |
| TSR → SW 요구사항 | SW 모듈 요구 + 추적성(RTM) 유지 |
| 시험 | 요구사항마다 검증, 안전 등급이 높을수록 커버리지·독립성 요구가 커짐 (→ `sw-testing.md`) |

## 4. VBC에 적용하는 방법 (설명용 예시, 사양서와 별개)
VBC는 차체 편의 기능이라 실제 ASIL 대상은 아닐 가능성이 높다. 다만 사양서의 몇몇 규칙은 HARA 사고방식으로 설명할 수 있어 발표·질의 대비에 쓴다.

### 4.1 사양서 규칙이 "안전 상태 쪽으로 기운 이유" 읽기
| 규칙 | 안전 관점 해석 | 해당 가이드워드 |
|---|---|---|
| C4 수신 중단 → 시동 OFF 간주, D1 잠금 유지 | 입력을 못 믿으면 **보수적 상태**(조명·와이퍼 정지, 잠금은 직전 유지)로 간다. 잠금이 풀려 버리는 것을 피함 | Failure to update |
| L5 조도 센서 고장 → 점등 | 센서를 못 믿을 때 **보이는 쪽**(점등)으로 안전 측 결정 | Loss of Function 대응 |
| W5 강우 센서 고장 → 간헐 와이퍼 | 센서 없이도 시야를 최소 확보 | Loss of Function 대응 |
| D3 속도 ≥15 → 자동 잠금 | 주행 중 의도치 않은 도어 열림 방지 | Unintended Activation 방지 |
| D4/D5 주행 중 도어 열림 경고가 최우선 | 경고 여럿이면 위험도가 가장 높은 것을 먼저 표시 | 우선순위 = 위험 크기 순 |
| C3 유효한 속도(0~250, 0.5초 이내) | 오래됐거나 범위 밖인 값으로 판단하지 않음 | Failure to update |

### 4.2 VBC 기능 오동작 식별 연습 (HAZOP 방식, 예시)
| 기능 | 가이드워드 | 오동작 | 사양서 대응 요구 | 시험 위치 |
|---|---|---|---|---|
| 전조등 | Loss of Function | 어두운데 점등 안 됨 | L2, L5, L6 | tests/test_lighting.c |
| 전조등 | Unintended Activation | 시동 OFF인데 점등 | L1 | 〃 |
| 전조등 | Failure to update | 조도 끊겼는데 이전 값으로 판단 | C2, L5 | test_core |
| 와이퍼 | Loss of Function | 폭우인데 정지 | W2, W5 | tests/test_wipers.c |
| 와이퍼 | Wrong Direction | 한 단계 낮추기(W3)가 반대로 적용 | W3 | 〃 |
| 도어 | Unintended Activation | 주행 중 잠금 해제 | D1~D3 | tests/test_doors.c |
| 계기판 | Loss of Function | 주행 중 도어 열림 경고 안 뜸 | D4, D5 | tests/test_dashboard.c |

### 4.3 위험사건 평가 예 (학습용, 값은 가정)
| 위험사건 | S | E | C | 가정 ASIL | 근거(가정) |
|---|---|---|---|---|---|
| 야간 고속 주행 중 전조등 미점등 | 3 | 3 | 2 | B | 야간 주행 빈도 중간, 운전자가 수동 점등 가능 |
| 주행 중 도어 잠금 해제로 도어 열림 | 3 | 4 | 3 | D | 상시 주행, 탑승자 통제 어려움 |
| 폭우 중 와이퍼 정지 | 2 | 2 | 2 | QM | 운전자가 수동 조작 가능 |

> 이 표는 **연습용 가정**이다. 실제 평가는 도메인 전문가와 해야 하며, 팀 결과물에 ASIL을 쓰려면 사양서에 근거가 있는지 먼저 확인한다.

### 4.4 운영 원칙
- 기능을 "안전해 보이게" 임의로 바꾸지 않는다. 사양서에 없는 동작은 `docs/c-structure.md` 질의 후보에 올린다.
- 경계·장애 상황(범위 밖, 끊김, 첫 수신 전, 복귀) 시험은 HAZOP의 Loss/Failure to update 가이드워드를 시험 설계의 체크리스트로 쓰는 것과 같다.
- AI가 제안하는 "더 안전한" 동작도 사양서와 대조해 검증한다(`docs/verification.md`의 AI 오류 기록과 같은 원칙).
