# ECU 테스트 시뮬레이터 (BCU system 구성도) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TEST MODULE(modcon) 엔진을 터미널·WASM 공용으로 만들고, BCU 전체 콘솔(`con_ecu`)과 그것을 구성도로 보여 주는 브라우저 페이지(`sim/ecu.html`)를 만든다.

**Architecture:** `modcon.c`의 REPL과 엔진을 나눠 `modcon_exec/advance/state_json`을 공개한다. 콘솔 5개(ecu + 모듈 4개)는 정의 함수로 분리해 터미널 바이너리와 WASM(`sim/build/ecu.js`)이 같은 정의를 쓴다. 화면은 엔진에 명령 문자열을 넣고 state JSON을 SVG로 그리기만 한다.

**Tech Stack:** C11 (gcc, emcc), Python 3 (run_tc.py), 바닐라 JS ES 모듈 + SVG, Node 24 (emsdk 동봉, 검증용)

**Spec:** `docs/superpowers/specs/2026-10-13-ecu-sim-design.md`

## Global Constraints

- `src/` 제품 코드, `src/common.h`, `src/vbc.h`는 바꾸지 않는다.
- 기존 TC 파일 `tools/consoles/tc/{doors,dashboard,lighting,wipers}.txt`는 바꾸지 않는다. 기대값은 사양서 VBC-SRS-001 v1.0에서 계산한다.
- 기존 REAL SIM(`sim/index.html`, `sim/js/*.js`, `sim/js/scene/*`)은 바꾸지 않는다.
- 터미널 콘솔(`make con-*`, `make tc`)의 출력 문자열은 그대로 둔다 (리팩터 전후 로그 diff 0).
- 화면 JS에는 요구사항 판단(`lux < 1000` 같은 비교)을 넣지 않는다. 값 → 색·라벨 매핑만.
- 의존성 추가 없음 (npm 패키지, Python 패키지, JS 라이브러리 모두).
- 시간은 엔진의 `now`만 쓴다. C 쪽에 `time()`·`sleep()` 금지.
- 커밋 메시지에 요구사항 ID를 붙인다 (C1~C5, L6, D5 등). 브랜치 `test/ecu-sim`.
- 주석·메시지는 한국어, 주변 코드와 같은 밀도·말투.

## Review Focus

1. **정의 안 된 코드**(gear 7, ign 2, light -1, speed INT32_MIN) → state JSON이 깨지지 않고(`JSON.parse` 성공) enum 출력은 `"INVALID"`. → Task 3 `wasm_check.mjs` "odd codes".
2. **엔진 모드에서 인자 없는 명령**(`t`, `speed`, `lock`, 메뉴 번호 `3`) → 입력을 기다리지 않고 오류(1) 반환. → Task 1 엔진 확인, Task 3 "no-arg".
3. **판단 주기를 바꾼 뒤 분할 재생**(`period step 50` → `t 0.125`) → 터미널과 같은 판정 시각. → Task 3 "period chunk".
4. **재생 중 콘솔 전환** → 이전 콘솔 상태가 섞이지 않고 C5에서 시작. → Task 3 "switch resets".
5. **TC 파일 끝까지 재생 후 요약** → `modcon_finish` 요약 줄이 터미널과 같음. → Task 3 동일성 비교에 요약 줄 포함.

**Interfaces:**
- Produces (`modcon.h`):
  ```c
  enum { SWC_LIGHTING = 1 << 0, SWC_WIPER = 1 << 1, SWC_DOORS = 1 << 2, SWC_DASHBOARD = 1 << 3 };
  /* ModCon 정의부에 추가 */ const char *name; /* "doors" 등, TC 파일명·JSON용 */  unsigned swc; /* SWC_* */
  /* ModCon 실행부에 추가 */ bool interactive; /* modcon_run이 켬: 인자 없으면 되묻기 */  bool err; /* 이번 명령에서 '!' 오류 */
  void modcon_start(ModCon *m);                  /* 카운터 0, reset (C5, 0초 첫 송신) */
  int  modcon_exec(ModCon *m, const char *line); /* 0 OK, 1 오류('!' 출력), 2 quit */
  int  modcon_advance(ModCon *m, long ms);       /* 진행, 바뀐 출력·판정 수 반환. "변화 없음"은 출력 안 함 */
  int  modcon_finish(ModCon *m);                 /* TC 마무리 + 요약 줄. FAIL 있으면 1 */
  int  modcon_run(ModCon *m);                    /* 터미널 REPL (기존 동작) */
  ```
- Produces (`consoles.h`): `void con_ecu_define(ModCon *m); void con_doors_define(ModCon *m); void con_dashboard_define(ModCon *m); void con_lighting_define(ModCon *m); void con_wipers_define(ModCon *m);` (`con_ecu_define`은 Task 2에서 구현)

  - `"  ! ..."`를 내는 모든 `printf`를 `static void oops(ModCon *m, const char *fmt, ...)`(vprintf + `m->err = true`)로 바꾼다. 문자열은 그대로.
  - `read_line`으로 되묻는 4곳(`t` 인자 없음, 상태 명령 인자 없음, `ask_and_set`, 메뉴 번호)은 `!m->interactive`이면 `oops(m, "  ! %s: 값을 함께 입력하세요 (h 도움말)\n", cmd)`.
  - `advance()` → `modcon_advance()`: 마지막 `"변화 없음"` printf를 빼고 changes 반환. `t` 명령 처리부가 반환값 0이면 같은 문장을 출력.

  - `modcon_start`: `tc[0]='\0'`, `tc_count = tc_failed = checks = failures = observations = 0`, `tc_has_fail = false`, `reset(m)`.
  - `modcon_finish`: 기존 `modcon_run` 끝의 `tc_close` + 요약 printf, `failures ? 1 : 0` 반환.
  - `modcon_run`: `m->interactive = true; modcon_start(m);` 배너 → 루프에서 `modcon_exec`(2면 종료) → `return modcon_finish(m);`

static void mod_step(ModCon *m)

```
step = engine.state().step_ms   // t 줄을 만날 때 한 번 읽는다
carry += budgetMs
while (R > 0):
    if R < step: n = R                         // 마지막 나머지 조각
    else: n = min(R - R % step, floor(carry / step) * step); if n == 0: break
    engine.advance(n); R -= n; carry = max(0, carry - n)
```
각 조각이 step의 배수(마지막 나머지만 예외)라 판단 시각이 터미널 `t`와 같다. 한 `t` 줄 동안 `advance` 반환 합이 0이면 엔진과 같은 문장 `  → X.XXX초 동안 변화 없음`을 로그. 파일 끝이면 `engine.finish()`, `== 시나리오 끝` 로그, `active = false`. `next()`: 남은 `t`가 있으면 끝까지 진행, 없으면 다음 줄 하나 실행.
