## 1. 개요

전방 레이더 3개(4D 이미징 1, 전방 측면 2)로 차량 앞 150 m를 덮는 전방 집중형 맵을 만들고, 그 맵으로 0~60 km/h 정체 구간에서 선행 차량을 따라 서고 다시 출발하는 Stop & Go를 추가한다. 이 문서는 VBC-SRS-001 6.2(개발팀 추가 기능)의 형식(ID, 조건, 동작, 수치)을 따르는 가정 요구사항이다.

### 1.1 가정

- 레이더는 실제 4D 레이더처럼 **검출점 목록**(거리, 방위각, 고도, 도플러 속도, 신호 세기)을 보낸다. 점을 물체로 묶고(군집화) 추적·융합하는 것은 이 소프트웨어의 일이다(4장).
- 시뮬레이터에서는 레이더 하드웨어를 **센서 모델**이 대신한다. 센서 모델은 장면의 물체·교통 참여자를 시야, 분해능, 잡음, 검출 확률, 가림을 거쳐 검출점으로 바꾼다(8장). 제품 소프트웨어는 센서 모델의 내부를 보지 않고 프레임만 받는다.
- 조향 입력이 없다(VBC-SRS-001에 조향 신호 없음). 자차 경로는 **직진**으로 본다.
- Stop & Go는 가속도를 직접 만들지 않고 **목표 가속도와 정지 유지를 요청**한다. 요청을 받아 속도를 바꾸는 것은 주행 모델(R1~R5)이다.
- 긴급 제동(AEB), 차선 유지, 조향 제어는 범위 밖이다.

### 1.2 범위

| 구분 | 기능 | 관련 절 |
|---|---|---|
| 추가(X) | 레이더 수신·유효성(끊김, 반복, 고착), 시작 상태 | 3 (XC) |
| 추가(X) | 전방 집중형 맵: 군집화, 추적, 융합, 선행 차량 선택 | 4 (XM) |
| 추가(X) | Stop & Go: 정속·추종·정지·재출발·해제, 레이더별 제한 | 5 (XS) |
| 변경 요청 필요 | 계기판 알림 칸 추가(XD), 주행 모델의 가속도 요청·정지 유지 입력(XR) | 6 |
| 시뮬레이터 | 레이더 센서 모델(가상 하드웨어), 교통 참여자, 고장 주입 | 8 (XH) |

### 1.3 용어

| 용어 | 뜻 |
|---|---|
| 차량 좌표 | 원점 = 앞 범퍼 가운데 노면, x 전방(+), y 왼쪽(+), z 위(+). 단위 m |
| 객체 | 레이더 한 주기에서 보고된 물체 하나 |
| 트랙 | 여러 주기에 걸쳐 같은 물체로 묶인 객체. 확정 트랙만 제어에 쓴다 (XM4) |
| 경로 내 | 자차가 직진할 때 지나갈 폭. 트랙 가로 범위가 \|y\| ≤ 1.3 m와 겹침 (XM8) |
| 선행 차량 | 경로 내 확정 트랙 중 가장 가까운 이동 또는 정지 차량 (XM9) |
| 차간 시간 | 선행 차량까지 거리를 자차 속도로 나눈 값(s). 운전자가 1.0 / 1.5 / 2.0 s 중 고름 |
| TTC | 충돌까지 시간 = 거리 ÷ 접근 속도. 멀어지면 계산하지 않음 |
| Stop & Go 상태 | 꺼짐 / 대기 / 작동 / 정지 유지 / 재출발 대기 (5장) |

### 1.4 요구사항 표기

VBC-SRS-001 1.4에 따라 X 계열을 쓰고, 묶음별로 XC(공통), XM(맵), XS(Stop & Go), XR(주행 모델 연결), XD(계기판), XH(시뮬레이터 센서 모델)를 붙인다. 구분 "추가"는 이 기능을 구현할 때 반드시 확인하는 항목이다. 검증란의 "테스트"는 입력 주입 자동 시험, "시연"은 시뮬레이터 화면 확인이다. 기존 C·L·W·D·R 규칙은 그대로 유지한다.

## 2. 시스템 구성과 입력·출력

레이더 3개가 50 ms마다 객체 목록을 보내면, 맵이 이를 하나의 트랙 목록과 선행 차량으로 묶고, Stop & Go가 선행 차량·차량 상태·운전자 입력으로 목표 가속도를 정한다.

> (그림: 시스템 구성 · 센서 3, 판단 2, 출력 2 — Claude Docs 원본 문서에만 있음)

주행 모델이 바꾼 속도는 다시 차량 상태 입력으로 돌아와, Stop & Go는 기존 VBC와 같은 C3·C4 유효성을 거친 속도만 쓴다.

### 2.1 센서 배치

| 센서 | 장착 | 시야(수평 / 수직) | 거리 | 맵에서 맡는 일 |
|---|---|---|---|---|
| 전방 4D 이미징 레이더 (FR) | 앞 범퍼 가운데, 정면 | ±60° / ±15° | 0.5~200 m | 원거리 선행 차량, 높이(z)로 육교·표지판·노면 이음매 구분 |
| 전방 좌측 레이더 (FCL) | 앞 범퍼 왼쪽 모서리, 왼쪽 45° | ±75° / - | 0.2~80 m | 근거리 끼어들기, 정지 중 앞 횡단 물체 |
| 전방 우측 레이더 (FCR) | 앞 범퍼 오른쪽 모서리, 오른쪽 45° | ±75° / - | 0.2~80 m | FCL과 대칭 |

### 2.2 입력

| 항목 | 유효한 값 | 비고 |
|---|---|---|
| 프레임 머리 (FR, FCL, FCR 각각) | 센서 ID, 카운터 0~255, 상태 정상 / 고장 / 가림 | 50 ms마다. 카운터는 새 프레임마다 1씩 늘고 255 다음 0. 가림 = 오염·눈으로 시야 막힘 |
| 검출점 (FR) | 최대 512개 | 점마다 거리 0.5~200 m, 방위각 −60~+60°, 고도각 −15~+15°, 도플러 속도 −70~+70 m/s(다가오면 음수), 신호 세기(SNR) 0~60 dB |
| 검출점 (FCL, FCR) | 각 최대 128개 | 거리 0.2~80 m, 방위각 −75~+75°(센서 정면 기준), 도플러 −70~+70 m/s, SNR 0~60 dB. 고도각 없음 |
| 장착 정보 | 센서별 위치(x, y, z), 방향 | 고정값(8.1). 검출점을 차량 좌표로 바꿀 때 쓴다 |
| 속도·기어·시동·도어 4개 | VBC-SRS-001 3.1 | 유효성은 C3·C4를 그대로 쓴다 |
| 브레이크·가속 페달 | 밟음 / 안 밟음 | 주행 모델(R4)의 입력과 같은 값 |
| Stop & Go 스위치 | OFF / ON | ON이면 대기 상태가 된다 |
| SET / RES 버튼 | 눌림 / 안 눌림 | SET = 작동 시작·설정 속도 저장, RES = 재출발 또는 이전 설정으로 복귀 |
| 차간 시간 스위치 | 1 / 2 / 3 | 1.0 / 1.5 / 2.0 s. 시작값 2 |
| 설정 속도 +/− | 눌림 | 10 km/h씩 30~60 km/h 안에서 |

검출점이 0개여도 프레임은 50 ms마다 계속 들어와야 한다. 하나의 물체는 보통 여러 점으로 보이고, 매 프레임 값에 잡음이 있다. 같은 카운터가 다시 오면 새 프레임이 아니다(XC1).

### 2.3 출력

| 항목 | 값 | 받는 곳 |
|---|---|---|
| 목표 가속도 요청 | 없음 / −3.5~+1.5 m/s² | 주행 모델 |
| 정지 유지 요청 | 없음 / 유지 | 주행 모델 (속도 0에서 차를 세워 둠) |
| 전방 맵 | 확정 트랙 목록(ID, x, y, 속도, 정지/이동, 출처 센서), 선행 차량 ID, 맵 상태(정상 / 축소 / 없음) | Stop & Go, 화면 |
| Stop & Go 상태 | 꺼짐 / 대기 / 작동 / 정지 유지 / 재출발 대기, 설정 속도, 차간 시간 | 계기판 |
| 계기판 알림 | 없음 / 운전자 개입 요청 / 출발 가능 / 레이더 고장 | 계기판 (6장의 우선순위) |

## 3. 공통 규칙 (XC)

레이더는 새 프레임이 0.2초 없거나, 검출점이 1초 동안 그대로이거나, 스스로 고장·가림을 보내면 고장으로 보고, 정상 프레임이 1초 이어져야 복귀한다. 차량 상태의 유효성은 VBC-SRS-001 C3·C4를 그대로 따른다.

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XC1 | **새 프레임 없음**: 새 프레임은 카운터가 직전과 다른 프레임이다. 같은 카운터로 다시 온 프레임(프레임 반복)은 쓰지 않는다. 한 레이더의 새 프레임이 0.2초 동안 없으면 그 레이더는 고장이다. 처음 프레임이 들어오기 전에는 시작 시점부터 센다. | 추가 | 테스트 |
| XC2 | **레이더 자체 상태**: 레이더가 고장 또는 가림을 보내면 그 프레임부터 그 레이더는 고장이고, 그 프레임의 검출점은 쓰지 않는다. | 추가 | 테스트 |
| XC3 | **검출점 값 범위**: 검출점의 값 중 하나라도 2.2의 유효 범위 밖이면 그 점만 버린다. 레이더는 고장으로 보지 않는다. 최대 개수를 넘는 점은 쓰지 않는다. | 추가 | 테스트 |
| XC4 | **차량 상태**: Stop & Go의 속도 조건은 유효한 속도(C3)일 때만 성립한다. 차량 상태 수신 중단(C4)이면 Stop & Go는 XS11에 따라 해제한다. | 추가 | 테스트 |
| XC5 | **N초 연속**: 이 문서의 "N초 연속"은 C1과 같다. 조건이 깨지면 처음부터 다시 센다. | 추가 | 테스트 |
| XC6 | **시작 상태**: 맵 비어 있음, 선행 차량 없음, Stop & Go 꺼짐, 설정 속도 없음, 차간 시간 1.5 s, 가속도 요청 없음, 정지 유지 요청 없음, 알림 없음. 세 레이더는 처음 프레임을 받기 전까지 고장이 아니라 "확인 중"이며, Stop & Go는 켜지지 않는다. | 추가 | 테스트 |
| XC7 | **값 고착**: 카운터는 늘어나는데 자차가 유효한 속도 4 km/h 이상으로 움직이는 동안 검출점 목록이 1초 연속 값까지 똑같으면 그 레이더는 고장이다. 점이 0개인 프레임은 센하지 않는다(빈 도로는 정상). | 추가 | 테스트 |
| XC8 | **복귀**: XC1·XC2·XC7로 고장이 된 레이더는 고장 조건 없이 새 프레임이 1초 연속 들어와야 정상으로 돌아간다. | 추가 | 테스트 |

0.2초(4주기)는 VBC의 0.5초보다 짧다. 60 km/h에서 0.5초면 8.3 m를 모르고 지나기 때문이며, 값은 질의 후보로 올린다(7장 Q1).

## 4. 전방 집중형 맵 (XM)

맵은 세 레이더의 검출점을 차량 좌표로 바꾸고, 점을 군집으로 묶고, 군집을 트랙으로 추적해 x 0~150 m, |y| ≤ 10 m를 50 ms마다 갱신한다. 3주기 연속 이어진 트랙만 확정하고, 그중 경로 내 가장 가까운 장애물을 선행 차량으로 고른다. 원거리는 4D 레이더, 앞 모서리 근거리는 측면 레이더가 맡고, 높이는 4D 레이더만 잰다.

XM1~XM7은 맵을 만드는 순서이고, XM8~XM10은 그 결과로 판단한다.

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XM1 | **맵 영역**: 맵은 x 0~150 m, \|y\| ≤ 10 m 안의 검출점·트랙만 담는다. 측면 레이더 검출점은 x 0~40 m 안의 것만 쓴다. | 추가 | 테스트 |
| XM2 | **갱신****·좌표 변환**: 50 ms마다 갱신하고, 프레임이 들어온 뒤 100 ms 안에 맵에 반영한다. 검출점은 장착 정보로 차량 좌표(x, y, z)로 바꾼다. 점의 지면 속도 = 도플러 + 자차 속도 × (시선과 x축의 cos)이고, \|지면 속도\| < 0.5 m/s면 정지 점이다. FR 정지 점 중 z < 0.15 m + 고도 잡음 3σ(거리 × 0.1° × 3)인 노면 점은 군집에 넣지 않는다. | 추가 | 테스트 |
| XM3 | 군집화와 **융합**: 한 프레임에서 같은 레이더의 점 중 서로 x 1.5 m, y max(1.0 m, 방위 분해능 1.5칸 × 거리), 도플러 1.0 m/s(FR은 높이 차 1.0 m도) 안으로 이어지는 점을 한 군집으로 묶는다. 군집 위치는 가장 가까운 x와 y 평균, 높이는 FR 점의 z 최저·최고다. 레이더가 달라도, 같은 레이더의 군집 여러 개라도 같은 트랙에 연관되면 한 물체로 합치고, 그 주기에 FR 군집이 있으면 FR 값을 쓴다. | 추가 | 테스트 |
| XM4 | **추적과**** 확정**: 50 ms마다 트랙을 예측하고, 군집을 게이트(x 2.5 m, y 1.5 m. 확정 전 트랙은 x 1.0 m, y 0.6 m. FR 측정은 높이 범위가 1.0 m 안에서 겹칠 때만) 안의 가장 가까운 트랙에 연관한다. 연관되지 않은 군집은 새 트랙이 된다. 3주기(0.15초) 연속 연관된 트랙이 확정 트랙이다. 매 프레임 다른 곳에 생기는 노면 잡음은 확정되지 않는다. 확정 전의 트랙은 Stop & Go에 쓰지 않는다. | 추가 | 테스트 |
| XM5 | **트랙 유지와 삭제**: 확정 트랙이 보이지 않으면 마지막 속도로 위치를 예측해 0.3초까지 유지하고, 그 뒤 지운다. 다시 보이면 같은 ID를 이어 쓴다. | 추가 | 테스트 |
| XM6 | **높이 거르기 (4D)**: z 최저값이 2.5 m 이상(육교·표지판)인 트랙은 움직임과 관계없이 장애물이 아니다(밑으로 지나갈 수 있음). 한 번도 움직이지 않은 정지 트랙 중 z 최고값이 0.2 m 미만(맨홀·노면 이음매)이거나, FR 시야 안인데 FR이 한 번도 보지 못한 측면 레이더 트랙(측면 오검출)도 장애물이 아니며, 이 판정은 정지해 있는 동안 유지한다(가까이 와서 FR 시야를 벗어나도). | 추가 | 테스트 |
| XM7 | **정지·이동 구분**: 자차 속도에 상대속도를 더한 지면 속도가 \|vx\| < 0.5 m/s이고 가로 속도가 \|vy\| < 1.0 m/s이면 정지 물체다. 지면 속도 1.5 m/s 이상 또는 가로 속도 1.0 m/s 이상이 0.25초(5주기) 이어지면 '움직였음'이고, 멈춰도 XM6의 낮은 물체·측면 오검출 판정을 하지 않는다. 폭이 3 m를 넘는 트랙(육교·가드레일)은 가로 속도를 보지 않는다. | 추가 | 테스트 |
| XM8 | **경로 내 판정**: 확정 트랙의 가로 범위(y 최소~최대)가 −1.3~+1.3 m와 겹치면 경로 내다 (예측 경로: 요레이트 센서 값 ÷ 속도로 곡률을 구하고, 앞 x m에서 경로가 곡률 × x² / 2만큼 옆으로 휘었다고 보고 판정. 1 m/s 아래나 요레이트 0이면 직진. 폭은 차폭 1.9 m 절반 + 여유 0.35 m). | 추가 | 테스트 |
| XM9 | **선행 차량 선택**: 경로 내 트랙 중 x가 가장 작은 것이 선행 차량이다. 다른 트랙이 경로 내로 들어와 지금 선행 차량보다 가까워지면(끼어들기) 0.3초 연속일 때 바꾼다. 선행 차량이 \|y\| > 1.8 m로 0.5초 연속 벗어나면 선택을 푸는다. | 추가 | 테스트 |
| XM10 | **센서 고장 시 맵 상태**: 세 레이더가 정상이면 "정상", FR은 정상이고 측면 레이더 하나 이상이 고장이면 "축소"(고장 쪽 근거리 비어 있음 표시), FR이 고장이면 "없음"이다. "없음"이면 선행 차량을 고르지 않는다. | 추가 | 테스트 |

## 5. Stop & Go (XS)

Stop & Go는 0~60 km/h에서 선행 차량을 차간 시간만큼 떨어져 따라가고, 선행 차량 뒤 4 m에 서며, 멈춘 지 3초 안에는 스스로, 3초가 지나면 운전자 입력으로 다시 출발한다. 운전자가 브레이크를 밟으면 그 주기에 해제한다.

우선순위: **XS10 > XS11 > XS8 > XS9 > XS12 > XS5·XS6·XS7 > XS4 > XS3**

> (그림: Stop & Go 상태 전이 · 5개 상태 — Claude Docs 원본 문서에만 있음)

켜진 상태 어디서든 브레이크·시스템 해제면 대기로 돌아가며, 서 있던 중이면 정지 유지 요청은 XS8에 따라 계속된다.

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XS1 | **켜기**: 시동이 켜져 있고 스위치가 ON이면 대기다. 대기에서 SET을 누르면 다음이 모두 맞을 때만 작동한다: 기어 D, 유효한 속도 0~60 km/h, 브레이크 안 밟음, 도어 4개 닫힘, 맵 상태 정상 또는 축소. 속도 0에서는 경로 내 선행 차량이 x ≤ 20 m에 있을 때만 켜지고, 정지 유지로 시작한다. 조건이 맞지 않으면 SET은 무시하고 대기를 유지한다. | 추가 | 테스트 |
| XS2 | **설정 속도**: SET을 누른 순간의 유효한 속도를 10 km/h 단위로 올려 저장하고, 30 미만이면 30으로 한다. +/−는 10 km/h씩 30~60 안에서 바꾼다. 대기에서 RES를 누르면 저장된 설정 속도로 XS1과 같은 조건에서 작동한다. | 추가 | 테스트 |
| XS3 | **정속**: 작동 중 선행 차량이 없으면 설정 속도를 목표로 한다. 가속도 요청은 −2.0~+1.5 m/s², 목표에 도달한 뒤 속도 오차는 ±2 km/h 이내다. | 추가 | 테스트 |
| XS4 | **추종**: 선행 차량이 있으면 목표 거리 d* = 4.0 m + 차간 시간 × 자차 속도(m/s)를 지키되 설정 속도를 넘지 않는다. 가속도 요청은 −3.5~+1.5 m/s², 변화율은 2.5 m/s³ 이하다(XS10·XS12 제외). 선행 차량이 일정 속도면 15초 안에 거리 오차가 1.0 m와 d*의 10 % 중 큰 값 이내가 된다. | 추가 | 테스트 |
| XS5 | **정지**: 선행 차량이 멈추면 자차는 선행 차량 뒤 4.0 ± 1.0 m에 멈춘다. 유효한 속도가 0이 되면 정지 유지로 바꾸고, 정지 유지 요청을 내며 가속도 요청은 없음으로 한다. | 추가 | 테스트 |
| XS6 | **자동 재출발**: 정지 유지가 3초 미만일 때 선행 차량이 출발하면(멈춘 때보다 x가 1.0 m 이상 길어지거나 지면 속도 1.0 m/s 이상) 0.5초 안에 정지 유지를 풀고 추종(XS4)으로 돌아간다. | 추가 | 테스트 |
| XS7 | **재출발 대기**: 정지 유지가 3초 연속되면 재출발 대기다. 이때는 스스로 출발하지 않는다. 선행 차량이 출발하면 "출발 가능" 알림을 내고, 운전자가 RES를 누르거나 가속 페달을 밟으면 재출발한다. | 추가 | 테스트 |
| XS8 | **장시간 정지·하차 준비**: 재출발 대기가 180초 연속되거나, 정지 유지·재출발 대기 중 도어가 열리거나 기어가 D가 아니게 되면 Stop & Go를 대기로 돌린다. 이때 정지 유지 요청은 기어가 P가 되거나 운전자가 브레이크를 밟을 때까지 계속 내고, 그동안 운전자 개입 요청을 표시한다. | 추가 | 테스트 |
| XS9 | **재출발 금지**: 재출발(XS6·XS7) 하려는 순간 다음 중 하나가 있으면 재출발하지 않고 정지 유지를 계속한다. (1) 경로 내 x ≤ 5 m에 정지할 때 앞에 있던 차량이 아닌 확정 장애물(새로 들어온 보행자가 선행 차량으로 뽑혀도 막는다). (2) 측면 레이더가 x ≤ 10 m, \|y\| ≤ 5 m에서 횡방향 속도 0.5 m/s 이상으로 경로 쪽으로 다가오는 트랙. (3) 맵 상태 "없음". 조건이 1초 연속 없어지면 금지가 풀린다. XS6의 3초는 금지 중에도 계속 센다. | 추가 | 테스트 |
| XS10 | **운전자 개입**: 브레이크를 밟으면 그 주기에 대기로 돌아가고 가속도·정지 유지 요청을 모두 없음으로 한다. 가속 페달을 밟는 동안에는 가속도 요청을 내지 않고(운전자 우선), 놓으면 작동으로 돌아간다. 스위치 OFF면 꺼짐이고, 정지 중이었다면 XS8과 같이 정지 유지를 계속한다. | 추가 | 테스트 |
| XS11 | **시스템 해제**: 작동·정지 유지·재출발 대기 중 다음 중 하나면 대기로 돌아간다: 시동 OFF, 기어 D 아님, 차량 상태 수신 중단(C4) 또는 유효한 속도 없음, 유효한 속도 70 km/h 초과, 맵 상태 "없음", 도어 열림. 주행 중 해제되면 가속도 요청을 1.0초에 걸쳐 0으로 줄인 뒤 없음으로 하고, 운전자 개입 요청을 5초 표시한다. 정지 중이면 XS8처럼 정지 유지 요청을 계속한다. | 추가 | 테스트 |
| XS12 | **충돌 위험**: 작동 중 선행 차량 TTC가 1.5초 미만이거나 멈추는 데 필요한 감속이 3.5 m/s²를 넘으면 운전자 개입 요청을 표시하고 −3.5 m/s²를 요청한다. TTC 2.5초 이상이 1초 연속되면 풀린다. (2.0초로 하면 멈춘 차에 정상으로 다가갈 때도 목표 거리 4 m + 1.5초 × v에서 TTC가 1.5 + 4/v초라 걸린다.) 긴급 제동(AEB)은 이 기능의 범위가 아니다. | 추가 | 테스트 |

| 고장한 레이더 | 켜기(XS1) | 작동 중 | 정지 중 |
|---|---|---|---|
| 없음 | 가능 | 계속 | XS6·XS7 |
| FCL 또는 FCR 하나 | 가능 | 계속 | 자동 재출발(XS6) 없음. 3초가 지나지 않아도 재출발 대기로 가고 RES·가속 페달로만 출발 |
| FCL과 FCR 둘 다 | 불가 | 계속. 멈추면 대기로(XS8처럼 정지 유지) | 재출발 금지, 정지 유지 |
| FR (다른 것과 관계없이) | 불가 | 해제(XS11) | 재출발 금지, 정지 유지 |

## 6. 안전, 주행 모델 연결, 계기판 표시

운전자 브레이크가 항상 이기고, 입력을 믿을 수 없으면 "더 가속하지 않는다, 서 있으면 서 있는다"로 간다. VBC의 C4(수신 중단이면 시동 OFF로 봄)·D1(잠금 유지)과 같은 보수적 방향이다.

### 6.1 안전 목표 (HARA, 학습용 가정)

| 위험사건 | 가이드워드 | S / E / C | 가정 ASIL | 막는 요구사항 |
|---|---|---|---|---|
| 정체 정지 중 앞에 보행자가 있는데 스스로 출발 | Unintended Activation | 3 / 3 / 3 | C | XS6, XS7, XS9 |
| 운전자가 브레이크를 밟았는데 가속 요청 계속 | Wrong Direction | 3 / 3 / 3 | C | XS10, XR1 |
| 선행 차량이 급감속하는데 감속 부족 | Less Than Requested | 3 / 4 / 2 | C | XM2, XS4, XS12 |
| 레이더가 끊겼는데 마지막 맵으로 계속 가속 | Failure to update | 3 / 2 / 3 | B | XC1, XC2, XM10, XS11 |
| 육교·맨홀을 장애물로 보고 급감속(유령 제동) | Unintended Activation | 2 / 3 / 2 | A | XM4, XM6 |
| 정지 유지 중 차가 밀려 나감 | Loss of Function | 2 / 3 / 2 | A | XS5, XS8, XR2 |

S·E·C와 ASIL은 ISO 26262-3 표로 만든 학습용 가정이다. 이로부터 안전 목표 세 가지를 둔다.

- SG1: 정지 중 의도하지 않은 출발을 막는다.
- SG2: 운전자 제동 중 시스템 가속을 막는다.
- SG3: 선행 차량에 대한 감속 부족을 막고, 못 막으면 운전자에게 넘긴다.

### 6.2 주행 모델 연결 (R 확장)

주행 모델은 운전자 브레이크 > 운전자 가속 > Stop & Go 요청 > 자연 감속(R4) 순서로 속도를 정한다.

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XR1 | 브레이크·가속 페달이 모두 안 밟혔고 목표 가속도 요청이 있으면, 주행 모델은 그 가속도로 속도를 바꾼다. 브레이크를 밟으면 요청과 관계없이 R4를 따른다. R1·R2·R5는 그대로 지킨다. | 추가 | 테스트 |
| XR2 | 정지 유지 요청이 있고 가속 페달을 안 밟았으면 속도 0을 유지한다. | 추가 | 테스트 |

### 6.3 계기판 표시

Stop & Go 알림은 D5의 계기판 경고와 **따로 두는 칸**에 한 번에 하나만 표시한다. D5를 바꾸지 않기 위해서다(합칠지는 7장 Q3).

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XD1 | 알림은 하나만 표시: 운전자 개입 요청 > 레이더 고장 > 출발 가능. 없으면 표시하지 않는다. | 추가 | 테스트 |
| XD2 | 시동이 켜져 있고 레이더가 하나라도 고장(XC1·XC2)이면 "레이더 고장"을 표시한다. Stop & Go 상태와 관계없다. | 추가 | 테스트 |
| XD3 | "출발 가능"은 XS7에서 켜고, 재출발하거나 5초가 지나거나 선행 차량을 잃으면 끈다. | 추가 | 테스트 |
| XD4 | Stop & Go가 꺼짐이 아니면 상태, 설정 속도, 차간 시간, 선행 차량 감지 여부를 표시한다. | 추가 | 시연 |

## 7. 검증 기준과 질의 후보

수치가 있는 요구사항은 모두 기준 직전 / 기준 / 직후의 3값으로 시험하고, 레이더 객체 목록을 직접 넣는 주입기로 확인한다. 기대값은 이 문서의 수치에서 계산한다.

### 7.1 경계값

|---|---|---|---|---|
| XC1 새 프레임 없음 | 0.2 s | 0.199 s 정상 | 0.200 s 고장 | 0.201 s 고장 |
| XC7 값 고착 | 1 s | 0.999 s 정상 | 1.000 s 고장 | 1.001 s 고장 |
| XC8 복귀 | 1 s | 0.999 s 고장 | 1.000 s 정상 | 1.001 s 정상 |

프레임은 50 ms마다 오므로 시간 경계(XC1·XC7·XC8)는 판단 주기를 1 ms로 두는 단위 시험에서 확인한다.

### 7.2 시험 장면

1. 정체 추종: 선행 차량 40 → 0 km/h(−2 m/s²), 2초 정지 후 30 km/h. 자동 재출발(XS4·XS5·XS6).
2. 같은 장면에서 5초 정지. 재출발 대기, "출발 가능", RES로 출발(XS7·XD3).
3. 정지 중 왼쪽 앞에서 보행자가 1.2 m/s로 횡단. 선행 차량이 출발해도 서 있음(XS9).
4. 옆 차로 차량이 자차 앞 8 m로 끼어듦. 0.3초 뒤 선행 차량 교체(XM9).
5. 육교(z 4.5 m) 아래 정지 차량, 그 앞 맨홀. 육교·맨홀은 무시, 차량은 선행 차량(XM6·XM7).
6. 추종 중 FR 끊김. 0.2초 뒤 레이더 고장, 해제, 가속도 1초에 0, 운전자 개입 요청(XC1·XM10·XS11).
7. 추종 중 브레이크. 그 주기에 대기, 요청 없음(XS10·XR1).
8. 추종 중 FR 프레임 반복(카운터 그대로). 0.2초 뒤 고장(XC1).
9. 추종 중 FR 값 고착(카운터만 늘어남). 1초 뒤 고장(XC7).
10. FCL 가림 상태에서 정체 추종. 멈춘 뒤 선행 차량이 출발해도 스스로 출발하지 않고 RES를 기다림(XS13).

|---|---|---|

| Q2 | 조향 입력이 없어 경로를 예측할 수 없다. 공선 도로에서 옆 차로 차량을 선행 차량으로 고를 수 있다 | 직진 경로 |

| Q4 | 주행 모델(R)에 가속도 요청·정지 유지 입력을 더해도 되는지 | XR1·XR2로 추가 |
| Q5 | 레이더 입력 형식 | 검출점 목록(2.2). 군집화·추적은 우리 소프트웨어, 하드웨어는 센서 모델(8장) |

## 8. 시뮬레이터: 레이더 센서 모델과 교통 (XH)

레이더 하드웨어 대신 센서 모델이 장면의 물체를 보고 50 ms마다 검출점 프레임을 만든다. 센서 모델은 판단을 하지 않고, 제품 소프트웨어(XC·XM·XS)는 프레임으로만 받는다. 같은 시나리오는 항상 같은 결과를 낸다.

### 8.1 센서 제원

| 항목 | FR (4D 이미징) | FCL / FCR (전방 측면) |
|---|---|---|
| 장착 (x, y, z) | (0, 0, 0.5 m), 정면 | (−0.2, ±0.75, 0.5 m), 바깥쪽 45° |
| 시야 방위 / 고도 | ±60° / ±15° | ±75° / ±8° (고도 출력 없음) |
| 거리 | 0.5~200 m | 0.2~80 m |
| 분해능 거리 / 방위 / 고도 / 속도 | 0.2 m / 1° / 2° / 0.1 m/s | 0.3 m / 2° / - / 0.2 m/s |
| 잡음 σ 거리 / 방위 / 고도 / 속도 | 0.05 m / 0.2° / 0.1° / 0.05 m/s | 0.1 m / 0.5° / - / 0.1 m/s |
| 기준 거리 R_ref (10 dBsm을 Pd 0.88로) | 200 m | 80 m |
| 최대 점 수 / 프레임 | 512 | 128 |

### 8.2 검출 모델

| ID | 요구사항 | 구분 | 검증 |
|---|---|---|---|
| XH1 | **시야·거리**: 시야와 거리 밖의 점은 내지 않는다. | 시뮬 | 테스트 |
| XH2 | **산란점**: 물체 상자의 센서 쪽 면에서 간격 max(0.4 m, 거리 × 방위 분해능)으로 점을 뽑는다. 물체당 센서당 최대 64점이며, 넘으면 간격을 넓혀 고르게 뽑는다. 아래에서 올려다보는 바닥면은 정반사로 돌아오지 않아 넣지 않는다. | 시뮬 | 테스트 |
| XH3 | **검출 확률**: 프레임마다 물체별로 여유 = RCS − 10 − 40·log10(거리 / R_ref) dB, Pd = 1 / (1 + e^−(여유 + 3)/1.5). 검출되면 각 산란점은 0.7 확률로 나온다. | 시뮬 | 테스트 |
| XH4 | **가림**: 센서에서 점까지 선분이 다른 물체 상자를 먼저 지나면 그 점은 나오지 않는다. | 시뮬 | 테스트 |
| XH5 | **측정값**: 거리·방위·고도·도플러(상대속도의 시선 성분)에 잡음을 더하고 분해능 칸으로 양자화한다. 같은 칸의 점은 하나로 합친다. SNR = 20 + 여유(0~60으로 제한). | 시뮬 | 테스트 |
| XH6 | **재현성**: 잡음·검출 확률은 시드가 고정된 의사난수로 만든다. | 시뮬 | 테스트 |
| XH7 | **클러터**: 오른쪽 가드레일(y −7.45 m, z 0.45~0.8 m)은 1 m마다 RCS −10 dBsm 점, 노면은 프레임마다 2~30 m 안 임의 위치에 0~3점(z 0, RCS −15 dBsm). | 시뮬 | 테스트 |
| XH8 | **고장 주입**(레이더마다 따로): 끊김(프레임 없음), 프레임 반복(직전 프레임을 카운터째 다시 보냄), 값 고착(카운터만 늘고 점은 고정), 가림(상태 '가림', 점 없음). | 시뮬 | 테스트 |

### 8.3 교통 참여자와 고정 물체

내 차로 가운데가 y 0이고, 오른쪽 차로는 y −3.6 m, 반대 방향 차로는 y +3.6 m와 +7.2 m다(차로 폭 3.6 m, 직선 도로). 실제 지도에서는 화면이 주행 경로와 경로 점마다 차로 범위(도로 폭·차로 수·일방통행)를 넘기고, 차·트럭은 경로를 따라 달리며 가로 위치가 그 자리의 차로 범위 안으로 제한된다(도로가 좁아지면 합류). 자차 자세와 요레이트는 화면이 매 프레임 알려 주므로 직접 운전으로 꺾어도 센서 모델은 실제 기하로 본다.

| 종류 | 길이 × 폭 × 높이 (m) | 높이 범위 z (m) | RCS (dBsm) | 움직임 |
|---|---|---|---|---|
| 승용차 | 4.6 × 1.9 × 1.5 | 0~1.5 | 10 | 목표 속도와 가감속, 차로 변경 |
| 트럭 | 10 × 2.5 × 3.5 | 0~3.5 | 20 | 승용차와 같음 |
| 보행자 | 0.5 × 0.5 × 1.75 | 0~1.75 | −5 | 가로질러 걷기 |
| 육교 | 10 × 30 × 1 | 4.5~5.5 | 25 | 고정 |
| 문형 표지판 | 0.3 × 16 × 1.5 | 5.0~6.5 | 15 | 고정 |
| 맨홀 뚜껑 | 0.8 × 0.8 × 0.03 | 0~0.03 | 5 | 고정 |

### 8.4 시나리오 명령

| 명령 | 뜻 |
|---|---|
| `obj add <종류> <앞 거리 m> <y m> [속도 km/h]` | 물체 추가. 종류: car, truck, ped, bridge, sign, manhole. 번호를 알려 준다 |
| `obj <번호> speed <km/h> [가감속 m/s²]` | 목표 속도 (기본 2 m/s²로 바뀜) |
| `obj <번호> lane <y m> [가로 속도 m/s]` | 차로 변경·횡단 (기본 1 m/s) |
| `obj <번호> del`, `obj clear` | 지우기 |
| `radar <fr\|fcl\|fcr\|all> ok\|cut\|repeat\|stuck\|block` | XH8 고장 주입 |
| `sg on\|off\|set\|res\|up\|down`, `sg gap 1\|2\|3` | Stop & Go 스위치·버튼 |

## 9. 구현하며 바뀐 것

실험 브랜치 `exp/radar-stop-and-go`에 센서 모델·맵·Stop & Go를 구현하고 시나리오 10개와 단위 테스트 38개를 돌리면서, 처음 정한 값 11개가 그대로는 맞지 않았다. 위 장들에는 바뀐 값을 이미 반영했다. 자세한 증거는 저장소 `docs/radar-stop-and-go.md`에 있다.

| 요구사항 | 처음 | 나타난 문제 | 바꾼 것 |
|---|---|---|---|
| XS12 | TTC 2.0초 | 멈춘 차에 정상 감속으로 다가가도 걸려 급제동, 11.9 m 앞에서 섬 | TTC 1.5초 (해제 2.5초) |
| XM3 | y 기준 1.0 m 고정 | 측면 레이더가 31 m 앞 차를 두 군집으로 쪼갬, 선행 차량이 오감 | 거리에 비례한 기준, 같은 트랙에 붙는 군집은 합침 |
| XM2 | 노면 점 제거 없음 | 저속에서 서 있는 앞차와 노면 잡음이 한 군집, 트랙이 1.3 m 튀어 급제동 | FR 높이로 노면 점을 버림 |
| XM6 | 정지·한 번도 안 움직인 것만 높이 거르기 | 조각난 육교·표지판 트랙이 가짜 가로 속도로 '움직였음', 가짜 선행 차량 | 바닥 2.5 m 이상은 무조건 무시 |
| XM4 | 연관에 높이를 안 봄 | 육교 아래 서 있는 차의 점이 육교 트랙에 붙음 | FR은 높이 범위가 겹칠 때만 연관 |
| XM6 | 측면 정지 물체 = 장애물 | 측면 노면 잡음이 우연히 이어져 5.6 m 앞 가짜 장애물 | FR 시야 안인데 FR이 못 본 측면 정지 물체는 오검출, 판정 유지 |
| XM7 | 가로 속도 추정 (감쇠 포함) | 실제의 0.55배, 횡단 보행자를 못 막음 | 표준 α-β, 도플러에서 가로 몫을 빼고 x 속도 |
| XM8 | 트랙 가운데 \|y\| ≤ 1.3 m | 폭이 넓거나 반쯤 들어온 물체를 놓침 | 가로 범위가 겹치면 경로 내 |
| XS9 | 선행 차량이 아닌 장애물 | 경로에 들어온 보행자가 선행 차량이 되어 RES가 통과 | 정지할 때 앞에 있던 차량이 아닌 장애물 |
| XS5 | 속도 0이고 요청 ≤ 0이면 정지 | 재출발 첫 주기에 다시 정지, 50 ms마다 오감 | 작동 0.5초 뒤부터 목표값으로 판단 |
| XH5 | 고도 σ 0.4° | 30 m에서 높이 오차 0.2 m, 맨홀과 장애물을 구분 못 함 | 0.1° (4D 레이더 수준) |

추종 제어 이득(0.25 → 0.45)과 정지 모드(4 m에서 서는 감속도)는 요구사항 값이 아니라 설계 값이라 여기에는 넣지 않았다. 이 값으로 서는 거리는 4.67 m다(XS5 합격).
