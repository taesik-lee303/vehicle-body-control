# 역할 분담 (5인)

원칙: 만든 사람 ≠ 검증하는 사람. 모든 모듈은 다른 사람이 리뷰하고 테스트를 교차 확인한다.

| 역할 | 담당 | 요구사항 | 교차 검증 |
|---|---|---|---|
| A. 코어·통합 (팀장) | 입력 수신, 시간 처리(C1~C4), 공통 상태 모델과 인터페이스, 메인 루프, CR-01 총괄 | C1~C5 | B, C, D의 C1~C4 사용 방식 |
| B. 조명 | 전조등 판단, 조도 센서 고장 표시 | L1~L6 | 담당: C |
| C. 와이퍼 | 와이퍼 단계, 강우 센서 고장 표시 | W1~W5 | 담당: D |
| D. 도어·잠금·경고 | 잠금 판단, 계기판 경고 우선순위 | D1~D5 | 담당: B |
| E. 계기판 | 계기판 경고 우선순위 | D1~D5 | 담당: E |
| F. 입력/시연·주행·기록 | 입력 조작 화면 또는 시나리오 파일, 출력 표시, 주행(R, 선택), 증명 기록 정리 | R1~R5, 시연 | 담당: A |

- X(추가 기능)는 필수 기능이 끝난 뒤 정한다. 요구사항 먼저 작성.
- 발표 질의에서 각자 자기 담당과 확인 방법을 설명해야 하므로, 모듈마다 테스트를 자기 손으로 설명할 수 있게 한다.

## 먼저 합의할 인터페이스
- 입력 상태: 속도, 기어, 시동, 조도, 강우량, 도어 4개, 조명 스위치, 와이퍼 스위치 + 각 값의 마지막 수신 시각
- 출력 상태: 전조등, 조도 고장, 와이퍼 단계, 강우 고장, 잠금, 계기판 경고
- 모듈 간 의존: 조명(L6)은 와이퍼 출력 단계를 입력으로 받음. 조명·와이퍼는 C4 수신 중단 시 시동 OFF로 간주. 도어(D)는 수신 중단 여부와 유효한 속도를 코어에서 받음
- 시간은 모듈이 직접 재지 않고 코어가 주는 시각(주입 가능한 시계)을 사용 → 2.9초/3초 경계 테스트 가능
