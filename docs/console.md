# 터미널 입력 (F 입력/시연)

## 실행
```bash
make            # build/vbc
./build/vbc     # 대화형: 명령을 한 줄씩 입력 (make run 과 같음)
./build/vbc scenarios/L2_dark_turns_on.txt   # 시나리오 파일 실행
make scenarios  # scenarios/*.txt 전부 실행, expect가 다 맞으면 PASS
```

## 동작 방식
```
명령 입력 ──► 패널 값 변경 ──► 그 시각에 바로 송신 + vbc_step ──► 바뀐 출력 표시
wait <초> ──► 0.05초마다 패널 값 전체를 다시 송신 + vbc_step ──► 바뀐 출력을 시각과 함께 표시
```
- **패널**은 "지금 보내고 있는 값"이다. 사양서 3.1에 따라 속도·기어·시동·조도·강우량은 값이 그대로여도
  계속 보내야 하므로, 시간이 흐르는 동안 0.05초마다 패널 값을 다시 보낸다.
  명령을 고민하는 동안 수신 중단(C4)이나 센서 고장(C2)이 생기지 않는다.
- **시간은 `wait`으로만 흐른다** (시뮬레이션 시간). 같은 명령이면 결과가 항상 같아서 2.9초/3초 같은 경계를
  그대로 보여 줄 수 있다.
- 값을 바꾸는 명령은 **현재 시각에 바로 송신**한다. `wait 2` 다음 `lux 300`이면 조도는 2.000초에 바뀐 것이다.

## 명령
| 분류 | 명령 | 설명 |
|---|---|---|
| 차량 상태 | `ign on\|off` | 시동 |
| | `gear P\|R\|N\|D` | 기어 |
| | `speed <km/h>` | 속도. 유효 0~250, 범위 밖 값도 그대로 보냄 (C3 시험) |
| | `lux <lux>` | 조도. 유효 0~60000 (범위 밖 → C2 고장) |
| | `rain <%>` | 강우량. 유효 0~100 |
| 주행 모델 (R) | `drive on\|off` | on: 속도·기어·시동을 운전 조작으로 만든다 (그때의 값을 이어받음). off: `speed`로 직접 입력 |
| | `pedal <스로틀> <브레이크>` | 스로틀 0 없음 / 1 보통(+10 km/h/s) / 2 풀(+25), 브레이크 0\|1(-40). 다음 `pedal`까지 유지. 가속+브레이크는 브레이크 우선 |
| 운전자 조작 | `door FL\|FR\|RL\|RR\|ALL open\|close` | 도어 |
| | `light off\|auto\|on` | 조명 스위치 |
| | `wiper off\|auto\|low\|high` | 와이퍼 스위치 |
| 고장 시험 | `cut speed\|gear\|ign\|lux\|rain\|vehicle\|all` | 송신 중단 (C2, C4). 값은 계속 바꿀 수 있음 |
| | `resume ...` | 송신 재개 (그 시각에 바로 보냄) |
| 시간·확인 | `wait <초>` | 시간 진행, 0.05초 단위 (예: `wait 2.9`) |
| | `show` | 입력·판정·출력 전체 |
| | `expect <항목> <값>` | 기대 확인 (아래 표). 틀리면 ✘ 표시, 시나리오 종료 코드 1 |
| | `reset` | 초기 상태(C5), 시각 0 |
| | `help`, `quit` | |

`#` 뒤는 주석. 명령과 값은 대소문자를 가리지 않는다.

시작 상태: 시동 OFF, 기어 P, 속도 0, 조도 30000(낮), 강우 0%, 도어 모두 닫힘, 스위치 OFF.

### expect 항목
| 항목 | 값 | 대상 |
|---|---|---|
| `headlight` | on / off | 전조등 |
| `luxlamp` | on / off | 조도 센서 고장 표시 |
| `wiper` | stop / int / low / high | 와이퍼 단계 |
| `rainlamp` | on / off | 강우 센서 고장 표시 |
| `lock` | on / off | 도어 잠금 (on = 잠김) |
| `warning` | none / door / lux / rain | 계기판 경고 |
| `rxlost` | on / off | (판정) 차량 상태 수신 중단 C4 |
| `ign` | on / off | 지금 보내는 시동 |
| `gear` | p / r / n / d | 지금 보내는 기어 |
| `speed` | 숫자(km/h) | 지금 보내는 속도 |

## 시나리오로 증명하기
요구사항 → 입력 → 기대 → 실제 → 증거를 파일 하나로 남긴다. `scenarios/<요구사항ID>_<설명>.txt`
```
# L2 어두우면 점등 (강의자료 48쪽 증명 예시)
ign on
light auto
lux 3000
wait 2
lux 300                 # 2.000초: 어두워짐
wait 0.9
expect headlight off    # 2.900초
wait 0.1
expect headlight on     # 3.000초
```
실행 로그(`build/<이름>.log`)를 그대로 PR과 `docs/verification.md`의 증거로 붙인다.
모듈 담당자는 자기 요구사항 시나리오를 추가하면 발표 시연에도 그대로 쓸 수 있다.

현재 상태: `L2_dark_turns_on`은 조명(B)이 구현되기 전이라 마지막 expect가 실패하는 것이 정상이다.

## 주행 모델 (R1~R5)
`drive on` 이후에는 `ign`, `gear`는 정지 상태(속도 0)에서만 받아들인다. 주행 중이면 `✘ 거부(R1/R2)`를 표시하고 값은 그대로다.
`speed`는 `drive off`일 때만 직접 입력할 수 있다. 가속 수치(팀이 정해 발표): 보통 +10, 풀 스로틀 +25, 브레이크 -40,
아무것도 안 누르면 -5 km/h/s, 최고 전진 250 / 후진 20 km/h (`src/drive.h`). 시나리오: `scenarios/R1~R5_*.txt`.
